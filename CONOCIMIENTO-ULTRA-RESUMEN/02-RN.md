# Conceptos del ecosistema React Native

Bullets para repaso de memoria — chequeo mental para entrevistas.

## Arquitectura

- **Hermes** — JS runtime optimizado para RN. Menos startup, memoria y bundle. Compila a bytecode.
- **ProGuard / R8** (Android) — reduce tamaño, optimiza y ofusca. **R8** es la versión nueva (estándar actual).
- **Yoga** — layout system (Flexbox). Solo calcula tamaño y posición de cajas; no dibuja UI.
- **Arquitectura vieja** — capa **Bridge**: comunicación asíncrona con cola entre JS (`UIManager`) y nativo. Mensajes JSON en batches → bottleneck.
- **New Architecture**
  - **JSI** — JS invoca objetos C++ nativos directamente, sin bridge JSON.
  - **Fabric** — nuevo renderer; reemplaza `UIManager`. Mejor sync Virtual DOM ↔ nativo.
  - **TurboModules** — módulos nativos lazy, tipados con Codegen.
  - **Codegen** — genera bindings type-safe JS ↔ nativo desde specs TypeScript/Flow.

## Config

- **Schemes / flavors / build variants** — una build por ambiente (`dev`, `staging`, `prod`): bundle id, APIs, íconos, variables, certificados propios.

## StyleSheet

- RN **no usa CSS** — estilos = objetos JS (`{ flex: 1, padding: 16 }`).
- `StyleSheet.create()` — valida props y optimiza IDs en runtime.
- **Flexbox por defecto** (Yoga): `flexDirection: 'column'` (web: `row`). No hay Grid ni cascade.
- Props clave: `flex`, `flexDirection`, `justifyContent`, `alignItems`, `alignSelf`, `flexWrap`.
- Unidades numéricas = **density-independent pixels** (no `px`, `rem`, `%` limitado).
- No hay selectors (`.class`), media queries tradicionales ni herencia CSS real.

## Otros

- **React Navigation** — estándar de navegación. Stack · Tabs · Drawer · Native Stack. Deep linking, nested navigators, lazy screens.
- **MMKV** — key/value síncrono, mmap. ~30× más rápido que AsyncStorage. Tokens, flags, cache liviana.
- **AsyncStorage** — async, solo strings, prefs simples. No sensibles ni datasets grandes.
- **Reanimated 2+** — animaciones en **UI thread** (no bloquea JS).
- **Gesture Handler** — gestos nativos de bajo nivel; base de navegación y gestures.
- **Native Modules** — Swift/Kotlin/ObjC/Java expuesto a JS.
- **Deep Linking** — abrir pantallas desde URLs o apps externas.
- **OTA Updates** — actualizar JS sin nueva build en stores (Expo Updates, CodePush).

## Lifecycle

- **AppState** — `active` · `background` · `inactive` (solo iOS). Pausar timers, refrescar al volver a foreground.
- **Component lifecycle** — igual que React: mount → re-render → unmount.
- Hooks RN típicos: `useEffect` · `useFocusEffect` (React Navigation, corre al focus/blur de screen) · `useMemo` · `useCallback`.

## Offline First

- **Objetivo** — app usable sin conexión.
- **Patrón** — leer cache local → UI inmediata → sync background → reconciliar.
- **Outbox / mutation queue** — mutación offline + optimistic UI → cola persistente (pending/syncing/failed) → FIFO al reconectar con retry.
- **Conflictos** — LWW, server wins, merge field-level, manual UI, version vectors (409).
- **Herramientas** — TanStack Query · SQLite · MMKV · WatermelonDB · Realm · SecureStore (tokens).
- **Regla** — local DB = source of truth inmediato; IDs temporales client-side hasta confirmación server.

## Preguntas clásicas

### ¿Cómo optimizás una app RN?

- **Listas:** FlatList/FlashList bien configuradas; evitar ScrollView con miles de items.
- **Animaciones:** Reanimated 2+ en UI thread.
- **React:** estado local o lift up state; evitar renders innecesarios.
- **Build:** Hermes habilitado; ProGuard/R8 en Android; strip dead code.
- **Imágenes:** tamaño correcto, cache (FastImage, expo-image), WebP donde aplique.
- **Timing:** `InteractionManager.runAfterInteractions`; lazy tabs; skeleton first; menos work en mount.

### ¿Cuándo usar FlatList vs ScrollView?

- **ScrollView** — pocos hijos de altura acotada (formularios, contenido estático). Renderiza **todos** los children de una vez — simple pero no escala.
- **FlatList** — listas dinámicas o largas. **Virtualiza**: solo monta items visibles + buffer. Feeds, chats, catálogos.
- **FlashList** (Shopify) — recycling agresivo, mejor FPS cuando FlatList no alcanza.
- **Regla:** scrollear más de ~20–30 items repetitivos → FlatList/FlashList.

### ¿Qué es Safe Area?

- Zona de pantalla que **no** se solapa con notch, Dynamic Island, status bar ni home indicator.
- `SafeAreaView` de `react-native-safe-area-context` (preferido sobre el de core).
- Padding automático para que contenido e interacciones queden en área usable.

### ¿Cómo funciona Flexbox en RN?

- Layout **100% Flexbox** vía Yoga (no block/inline como web).
- Default: `flexDirection: 'column'`, `alignItems: 'stretch'`.
- `flex: 1` — ocupa espacio disponible en el eje principal.
- `justifyContent` — distribución en eje principal; `alignItems` — en eje cruzado.
- Contenedor padre con dimensiones definidas (o `flex: 1`) para que hijos se posicionen bien.

### ¿Qué diferencias hay entre RN styling y CSS web?

| RN | Web |
|---|---|
| objetos JS | CSS/SCSS |
| sin DOM | DOM |
| sin cascade ni herencia | cascade CSS |
| sin selectors | `.class`, `#id` |
| sin media queries tradicionales | `@media` |
| Yoga / Flexbox only | layout engine completo |
| números = dp | `px`, `rem`, `%` |

### ¿Feature-based folders o layer-based?

- **Feature-based** (preferido mobile): `features/checkout/` con screens, hooks, components, api. Ownership por feature, menos coupling.
- **Layer-based:** `screens/`, `components/`, `services/` — todo mezclado, carpetas gigantes, imports cruzados.
