Alternativas de State Management

1. ¿Cuándo usarías Zustand?

  • State global moderado sin boilerplate de Redux.
  • Necesitás selectors y suscripciones granulares fuera de React (stores vanilla).
  • Prototipado rápido con TypeScript first-class.
  • Migración gradual — no requiere providers (aunque podés usar context para testing).

No ideal cuando: necesitás middleware ecosystem maduro de Redux, time-travel debugging crítico, o el equipo ya está estandarizado en RTK Query + slices.

API minimal: create((set) => ({ count: 0, inc: () => set(s => ({ count: s.count+1 })) }))

2. ¿Qué opinás de MobX?

MobX usa observables reactivos — mutás state “directamente” y MobX trackea dependencias y re-renderiza automáticamente. Menos boilerplate que Redux, modelo OOP/reactivo.

Pros: DX rápida para state complejo con muchas derivaciones; menos código.

Cons: Magia implícita (harder to debug sin disciplina); menos estándar en RN hoy; curva para equipos acostumbrados a flux unidireccional.

Opinión senior equilibrada: válido en codebases existentes MobX; para greenfield RN prefiero Zustand o RTK por predictabilidad y hiring pool.

3. ¿Qué usarías para server state?

TanStack Query (React Query) — default recommendation para cache server-side: stale-while-revalidate, dedup, pagination, infinite queries, optimistic updates.

Alternativas: RTK Query (si ya en Redux), SWR (web-focused, menos features), Apollo Client (GraphQL).

No uses Redux/Context/Zustand como cache de API manual — reinventás invalidation, dedup, background refetch.

4. ¿Qué diferencia hay entre UI state y server state?

UI StateServer State
Owned by cliente (modal, tab, form draft)Owned by servidor, cache en cliente
Sincrónico, efímeroAsíncrono, puede quedar stale
useState, Zustand, ContextReact Query, RTK Query
No necesita refetchInvalidation, retry, sync

Separarlos clarifica arquitectura y evita mezclar isLoading de fetch con isModalOpen en el mismo slice.

5. ¿Qué ventajas tiene React Query/TanStack Query?

  • Cache key-based con TTL (staleTime, gcTime).
  • Background refetch on focus/reconnect/mount.
  • Deduplicación automática de requests paralelos.
  • Hooks declarativos: loading, error, data out of the box.
  • Mutations con optimistic updates e invalidation.
  • Pagination/infinite scroll primitives.
  • Devtools excelentes.
  • Framework agnostic core (TanStack Query v5).

En RN: integrar con NetInfo para onlineManager, persist con async storage para offline.
