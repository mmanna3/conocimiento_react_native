# JavaScript — Fundamentos

Guía concisa para repaso. Los números marcan el orden sugerido de estudio.

## 1. ¿Qué es una closure?

Una **closure** es una función que recuerda el entorno léxico (variables del scope) donde fue *creada*, aunque ese scope ya terminó de ejecutarse. En la práctica: “la función lleva sus variables a cuestas”.

```js
function crearContador() {
  let n = 0;
  return {
    incrementar: () => ++n,
    leer: () => n,
  };
}

const c = crearContador();
c.incrementar();
c.leer(); // 1 — `n` sigue viva gracias a las closures
```

Se usan para encapsular estado privado, factories, callbacks y middleware. En React, los handlers y effects son closures; si capturan valores viejos, hablás de *stale closure* (ver Hooks de React).

---

## 2. ¿Qué es el scope léxico?

El scope se resuelve por **dónde está escrito el código**, no por dónde se invoca la función (a diferencia de `this`, que sí depende del call site en funciones normales).

```js
const x = 10;

function externa() {
  const x = 20;
  function interna() {
    console.log(x); // 20 — busca hacia arriba en la cadena léxica
  }
  return interna;
}
```

Bloques `{ }` con `let`/`const` crean scope de bloque; `var` solo respeta funciones, no bloques `if/for`.

## 3. Diferencia entre var, let y const

| | var | let / const |
|---|---|---|
| **Scope** | Función (o global) | Bloque |
| **Hoisting** | Sí, inicializada como `undefined` | TDZ hasta la línea de declaración |
| **Reasignación** | Sí | `let` sí; `const` no el binding, sí mutar el objeto |
| **Re-declarar en mismo scope** | Sí | No |

Bug clásico en entrevistas — loop con `var`:

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 3, 3, 3 — una sola `i` compartida

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 0);
}
// 0, 1, 2 — cada iteración tiene su propio `j`
```

En código moderno: `const` por default, `let` si reasignás, evitá `var`.

---

## 4. ¿Qué es hoisting y la Temporal Dead Zone (TDZ)?

**Hoisting:** antes de ejecutar el código, el motor registra declaraciones. Con `var`, la variable existe desde el inicio del scope como `undefined` hasta la asignación:

```js
console.log(a); // undefined (no ReferenceError)
var a = 1;
```

`let` y `const` también se “elevan”, pero quedan en la **TDZ** hasta la línea de declaración — acceder antes lanza `ReferenceError`:

```js
console.log(b); // ReferenceError
let b = 1;
```

Las `function declarations` se elevan completas (podés llamarlas antes en el mismo scope). Las `function expressions` con `const` siguen la TDZ.

## 5. ¿Cómo funciona el event loop?

JavaScript en el navegador/RN (JS thread) es **single-threaded**: una call stack. Lo asíncrono no es paralelismo de threads JS, sino delegar y retomar vía el event loop.

1. Ejecutás código síncrono en la stack hasta vaciarla.
2. Callbacks asíncronos (timers, I/O, DOM) van a colas.
3. Cuando la stack está libre, el loop drena **microtasks** (Promises, `queueMicrotask`) hasta agotarlas.
4. Luego toma un **macrotask** (ej. un callback de `setTimeout`) y repite.

```js
console.log('1');

setTimeout(() => console.log('2'), 0);

Promise.resolve().then(() => console.log('3'));

console.log('4');
// 1, 4, 3, 2 — los microtasks van antes que el siguiente macrotask
```

Entender esto explica por qué un `setInterval` “ve” valores viejos si cerró sobre ellos al crearse, y por qué bloquear la stack con CPU pesada congela la UI.

## 6. Promesas y async/await

Una **Promise** representa un valor futuro: `pending` → `fulfilled` o `rejected`. Encadena con `.then/.catch/.finally`; errores no capturados → `unhandled rejection`.

```js
async function fetchUser(id) {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) throw new Error(res.statusText);
  return res.json();
}
```

`async/await` es azúcar sintáctica sobre Promises: la función `async` siempre devuelve una Promise; `await` pausa esa función hasta resolver (sin bloquear el thread — cede al loop).

**Patrones útiles:** `Promise.all` (paralelo, falla si una falla) · `Promise.allSettled` (siempre espera todas) · `Promise.race` · timeouts con `AbortController`

## 7. ¿Cómo funciona this?

`this` depende de **cómo se llama** la función, no de dónde se definió (salvo arrow functions y bind explícito):

- Llamada normal: `this` = `undefined` en strict mode, o el objeto global en sloppy.
- `obj.metodo()`: `this` = `obj`.
- `new Fn()`: `this` = instancia nueva.
- `call/apply/bind`: fijás `this` manualmente.
- **Arrow functions**: no tienen `this` propio — heredan el del scope léxico envolvente (ideal para callbacks en clases React si no bindeás).

```js
const obj = {
  name: 'Ana',
  saludar() { return this.name; },
  saludarArrow: () => this?.name, // `this` del módulo/global, no de obj
};
```

## 8. Prototipos y herencia

JS usa **herencia prototípica**: cada objeto tiene un prototipo interno (`[[Prototype]]`, accesible como `Object.getPrototypeOf(obj)`). Si una propiedad no está en el objeto, se busca en la cadena de prototipos.

```js
function Persona(nombre) {
  this.nombre = nombre;
}
Persona.prototype.saludar = function () {
  return `Hola, ${this.nombre}`;
};

const p = new Persona('Ana');
p.saludar(); // busca en `p`, luego en Persona.prototype
```

Clases ES6 son azúcar sobre constructors + `prototype`. Para objetos planos, preferí composición; `class extends` cuando modelás jerarquías claras.

## 9. Pasar por valor vs por referencia

Primitivos (`number`, `string`, `boolean`, `null`, `undefined`, `symbol`, `bigint`) se pasan **por valor** — la función recibe una copia.

Objetos, arrays y funciones se pasan **por referencia al mismo objeto** — podés mutar el contenido y afecta al original:

```js
function agregarItem(carrito, item) {
  carrito.push(item); // muta el array original
}

const c = [];
agregarItem(c, 'pan');
console.log(c); // ['pan']
```

En React/RN esto motiva inmutabilidad en state: devolvé copias nuevas (`[...arr, x]`, `{ ...obj, key: val }`) para que la reconciliación detecte cambios.

## 10. == vs === y coerción

`===` (igualdad estricta) compara valor y tipo, sin conversión. `==` aplica reglas de coerción (legacy, difícil de predecir):

```js
0 == false;   // true
0 === false;  // false
'' == false;  // true
null == undefined; // true (único caso útil de ==)
null === undefined; // false
```

**Regla práctica:** usá `===` y `!==` salvo que quieras explícitamente `x == null` (cubre `null` y `undefined`). Para objetos, `===` compara referencia, no contenido profundo.

## 11. Copia superficial vs profunda

**Shallow copy** — un nivel nuevo, objetos anidados siguen compartiendo referencia:

```js
const original = { a: 1, nested: { b: 2 } };
const copia = { ...original };
copia.nested.b = 99;
console.log(original.nested.b); // 99
```

**Deep copy** — árbol independiente: `structuredClone(obj)` (moderno), o librerías para grafos con referencias circulares. `JSON.parse(JSON.stringify(x))` pierde `Date`, `undefined`, funciones y referencias circulares.

## 12. Debounce vs throttle

| | Debounce | Throttle |
|---|---|---|
| **Idea** | Ejecuta después de que dejás de disparar el evento | Como máximo una ejecución cada X ms |
| **Ejemplo** | Búsqueda al dejar de tipear 300 ms | Scroll o resize sin saturar |

```js
function debounce(fn, ms) {
  let t;
  return (...args) => {
    clearTimeout(t);
    t = setTimeout(() => fn(...args), ms);
  };
}

function throttle(fn, ms) {
  let last = 0;
  return (...args) => {
    const now = Date.now();
    if (now - last >= ms) {
      last = now;
      fn(...args);
    }
  };
}
```

En RN/React suelen vivir en custom hooks o librerías; conocer la diferencia evita re-renders y llamadas API excesivas.

## 13. Módulos ES (import / export)

ES Modules son estáticos: imports resueltos en parse time, tree-shakeables.

```js
// utils.js
export const PI = 3.14;
export default function suma(a, b) { return a + b; }

// app.js
import suma, { PI } from './utils.js';
```

- `export / export default` — API pública del módulo
- `import` — bindings en vivo para exports nombrados (read-only)
- CommonJS (`require`) aún aparece en Node tooling y configs; Metro/Bundlers unifican a ESM en app RN

## 14. Sintaxis moderna útil en entrevistas

```js
// Optional chaining — evita crashes por null/undefined
const ciudad = usuario?.direccion?.ciudad;

// Nullish coalescing — solo si null o undefined (no si 0 o '')
const limit = config.limit ?? 10;

// Destructuring
const { id, name } = user;
const [first, ...rest] = items;

// Spread / rest
const merged = { ...defaults, ...overrides };
function logAll(level, ...messages) { }
```

Conocer cuándo usar `??` vs `||` es pregunta frecuente: `||` trata `0` y `''` como falsy.

## 15. Closures, timers y valores “viejos” (sin React)

Antes de stale closures en hooks, el patrón aparece en JS puro: un callback asíncrono captura variables del scope donde se *creó*.

```js
function iniciar() {
  let count = 0;

  setInterval(() => {
    console.log(count); // siempre lee el `count` de iniciar
  }, 1000);

  return () => { count += 1; }; // si alguien llama esto, el interval ve el nuevo count
}
```

Acá hay **un solo** binding `count` — mutarlo o reasignarlo en el mismo scope lo ven todos los callbacks que cerraron sobre esa variable.

En React cada render crea **nuevos** bindings (`const [count, setCount] = ...`); un effect con `[]` deja timers cerrados sobre el render #1. Por eso existen deps, updaters funcionales y refs — ver Hooks de React.
