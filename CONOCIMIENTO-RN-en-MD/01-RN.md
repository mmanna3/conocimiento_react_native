# React Native 

## 1. Arquitectura

### 1.1. Piezas clave

| Pieza | Qué hace |
|---|---|
| **Hermes** | Runtime JS optimizado para RN. Reduce startup, memoria y tamaño del bundle. Compila JS a bytecode. |
| **Yoga** | Engine de layout (Flexbox). Calcula tamaño y posición; no renderiza UI. |
| **ProGuard / R8** (Android) | Eliminan código no usado, optimizan bytecode y ofuscan nombres. R8 reemplazó a ProGuard y es el estándar actual. |

### 1.2. Arquitectura vieja (Bridge)

- Comunicación JS ↔ nativo mediante el **Bridge**.
- Bridge **asíncrono**: mensajes serializados (JSON) en batches.
- Mucho tráfico JS/native → bottlenecks.

### 1.3. New Architecture

Reemplazo del Bridge por comunicación directa y módulos lazy.

| Componente | Rol |
|---|---|
| **JSI** | JS invoca objetos C++ nativos directamente. Elimina overhead del Bridge JSON. |
| **Fabric** | Nuevo renderer. Reemplaza gran parte del viejo `UIManager`. Mejor sync entre React Fiber y vistas nativas. |
| **TurboModules** | Reemplazo de Native Modules. Lazy loading, más performantes y type-safe. |
| **Codegen** | Genera bindings y tipos desde specs TS/Flow. Menos errores JS ↔ nativo. |

## 3. Styling

### 3.1. StyleSheet

- RN **no usa CSS real** — los estilos son objetos JS.
- `StyleSheet.create()` valida y optimiza en runtime.

```ts
const styles = StyleSheet.create({
  container: {
    flex: 1,
    padding: 16,
  },
});
```

### 3.2. Flexbox en RN

Layout por defecto vía Yoga, con diferencias respecto a web:

- `flexDirection: 'column'` es el default (en web: `row`)
- No hay CSS Grid
- Algunas props CSS no existen (`gap` es reciente y depende de versión)

Props principales: `flex`, `flexDirection`, `justifyContent`, `alignItems`, `alignSelf`, `flexWrap`

```tsx
<View
  style={{
    flexDirection: 'row',
    justifyContent: 'space-between',
    alignItems: 'center',
  }}
/>
```

### 3.3. RN vs CSS Web

| React Native | Web |
|---|---|
| estilos en objetos JS | CSS/SCSS |
| no hay DOM | DOM |
| no hay cascade real | cascade CSS |
| no hay selectors (`.class`) | selectors |
| no hay media queries tradicionales | media queries |
| Yoga / Flexbox | browser layout engine |
| unidades implícitas (`16`) | `px`, `rem`, etc. |

| Opción | Características |
|---|---|

## 6. Librerías y conceptos transversales

| Tema | Resumen |
|---|---|

## 7. Lifecycle

### 7.1. AppState

Estados: `active` · `background` · `inactive` (solo iOS)

**Uso típico:** pausar timers · refrescar datos · detectar retorno a foreground

```ts
AppState.addEventListener('change', callback);
```

### 7.2. Component lifecycle

Mismo lifecycle que React: mount → re-render → unmount.

**Hooks más usados en RN:** `useEffect` · `useFocusEffect` (React Navigation) · `useMemo` · `useCallback`

---

## 8. Offline First

**Objetivo:** que la app funcione sin conexión.

**Conceptos:** cache local · optimistic updates · sync diferido · retry queues · persistencia offline

**Herramientas:** React Query / TanStack Query · SQLite · MMKV · WatermelonDB · Realm

**Patrón típico:**

1. Leer cache local
2. Mostrar UI inmediata
3. Sync en background
4. Reconciliar cambios

## 9. Preguntas clásicas

### 9.1. ¿Cómo optimizás una app RN?

- **Listas:** FlatList/FlashList bien configuradas. Evitar ScrollView con miles de items.
- **Animaciones:** Reanimated 2+ en UI thread.
- **React:** evitar renders innecesarios, memoizar cuando aporta, estado local donde corresponde.
- **Build:** Hermes habilitado. R8/ProGuard en Android.
- **Imágenes:** tamaño correcto, cache, WebP donde aplique.
- **Timing:** `InteractionManager.runAfterInteractions`, lazy screens/tabs, menos trabajo pesado en mount.
- **Listas grandes:** no pasar objetos/funciones inline innecesarias como props.

### 9.2. ¿Cuándo usar FlatList vs ScrollView?

| | ScrollView | FlatList | FlashList |
|---|---|---|---|
| **Cuándo** | Pocos hijos, contenido acotado, formularios, estático | Listas dinámicas/largas | Igual que FlatList, listas muy exigentes |
| **Cómo** | Renderiza todo de una vez | Virtualización: solo visible + buffer | Recycling agresivo, mejor FPS |
| **Ideal para** | — | Feeds, chats, catálogos | Listas complejas con drops de FPS |

**Regla práctica:** más de ~20–30 items repetitivos → FlatList o FlashList.

### 9.3. ¿Qué es Safe Area?

Zona de pantalla que evita solaparse con notch, Dynamic Island, status bar y home indicator.

```tsx
import { SafeAreaView } from 'react-native-safe-area-context';
```

El contenido no queda tapado por hardware o UI del sistema.

### 9.4. ¿Feature-based folders o layer-based?

**Feature-based** (preferido en apps medianas/grandes):

```txt
features/
  checkout/
    screens/
    hooks/
    components/
    api/
```

Ventajas: ownership claro · menos acoplamiento · escala mejor · features autocontenidas

**Layer-based:**

```txt
screens/
components/
services/
hooks/
```

Problemas: carpetas gigantes · imports cruzados · ownership difuso
