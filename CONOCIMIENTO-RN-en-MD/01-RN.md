# React Native — Conceptos Clave

## Arquitectura

- **Hermes**: runtime de JavaScript optimizado para React Native. Reduce startup time, consumo de memoria y tamaño del bundle. Compila JS a bytecode.
- **Yoga**: engine de layout basado en Flexbox. Calcula tamaño y posición de los elementos, pero no renderiza UI.
- **ProGuard / R8 (Android)**:
  - eliminan código no usado (`tree shaking/minification`)
  - optimizan bytecode
  - ofuscan nombres
  - R8 reemplaza a ProGuard y es el estándar actual.

### Arquitectura vieja
- Comunicación JS ↔ nativo mediante el **Bridge**.
- Bridge asíncrono con mensajes serializados (JSON) en batches.
- Mucha comunicación JS/native podía generar bottlenecks.

### New Architecture

#### JSI (JavaScript Interface)
- JS puede invocar objetos C++ nativos directamente.
- Elimina el overhead del Bridge JSON.

#### Fabric
- Nuevo renderer.
- Reemplaza gran parte del viejo `UIManager`.
- Mejor sincronización entre React Fiber y vistas nativas.
- Prioridades de render más eficientes.

#### TurboModules
- Reemplazo moderno de Native Modules.
- Lazy loading.
- Más performantes y type-safe.

#### Codegen
- Genera bindings y tipos automáticamente desde specs TS/Flow.
- Reduce errores entre JS y código nativo.

# Styling

## StyleSheet
- RN no usa CSS real.
- Los estilos son objetos JS.
- `StyleSheet.create()` ayuda con validación y optimización básica.

```ts
const styles = StyleSheet.create({
  container: {
    flex: 1,
    padding: 16,
  },
});
```

---

## Flexbox en RN

RN usa Flexbox por defecto pero con diferencias respecto a web:

- `flexDirection: 'column'` es el default (en web es `row`)
- No existe CSS Grid.
- Algunas props CSS no existen (`gap` llegó recientemente y depende de versión).
- Todo layout pasa por Yoga.

Conceptos principales:
- `flex`
- `flexDirection`
- `justifyContent`
- `alignItems`
- `alignSelf`
- `flexWrap`

Ejemplo:

```tsx
<View
  style={{
    flexDirection: 'row',
    justifyContent: 'space-between',
    alignItems: 'center',
  }}
/>
```

---

## Diferencias RN Styling vs CSS Web

| React Native | Web |
|---|---|
| estilos en JS objects | CSS/SCSS |
| no hay DOM | DOM |
| no hay cascade real | cascade CSS |
| no hay selectors (`.class`) | selectors |
| no hay media queries tradicionales | media queries |
| usa Yoga/Flexbox | browser layout engine |
| unidades implícitas (`16`) | `px`, `rem`, etc |

# Storage

## AsyncStorage
- key/value storage asíncrono.
- Persistencia simple.
- Más lento para workloads grandes.

## MMKV
- storage síncrono basado en mmap.
- Mucho más rápido que AsyncStorage.
- Ideal para tokens, flags y cache liviana.

---

# Otros conceptos importantes

## Reanimated
- Animaciones corriendo en UI Thread.
- Mucho más fluido que usar JS thread.
- Fundamental para gestures y animaciones complejas.

## Gesture Handler
- Mejor manejo de gestos nativos.
- Base de muchos componentes modernos de navegación/gestures.

## Native Modules
- Código nativo expuesto a JS.
- Swift/Kotlin/ObjC/Java ↔ React Native.

## Deep Linking
- Abrir pantallas desde URLs o apps externas.

## OTA Updates
- Actualizaciones JS sin publicar nueva build.
- Ej: Expo Updates, CodePush.

- `inactive` (iOS)

# Offline First

# Preguntas Clásicas

## ¿Cómo optimizás una app RN?

- FlatList/FlashList bien configuradas.
- Evitar ScrollView con miles de items.
- Reanimated 2+ para animaciones en UI thread.
- React bien usado:
  - evitar renders innecesarios
  - memoización cuando aporta valor
  - estado local donde corresponde
- Hermes habilitado.
- R8/ProGuard en Android.
- Imágenes optimizadas:
  - tamaño correcto
  - cache
  - WebP donde aplique
- `InteractionManager.runAfterInteractions`
- Lazy screens/tabs.
- Reducir trabajo pesado en mount.
- Evitar pasar objetos/funciones inline innecesarias en listas grandes.

---

## ¿Cuándo usar FlatList vs ScrollView?

### ScrollView
- pocos hijos
- contenido acotado
- formularios simples
- contenido estático

Renderiza todo de una vez.

### FlatList
- listas dinámicas/largas
- virtualización
- monta solo lo visible + buffer

Ideal para:
- feeds
- chats
- catálogos

### FlashList
Alternativa de Shopify:
- recycling agresivo
- mejor FPS
- menos drops en listas complejas

Regla práctica:
- si hay más de ~20-30 items repetitivos → FlatList/FlashList.

---

## ¿Qué es Safe Area?

Zona segura de pantalla que evita:
- notch
- Dynamic Island
- status bar
- home indicator

Se suele usar:

```tsx
import { SafeAreaView } from 'react-native-safe-area-context';
```

Permite que el contenido no quede tapado por elementos físicos/sistema del dispositivo.

## ¿Feature-based folders o layer-based?

### Feature-based (preferido)

```txt
features/
  checkout/
    screens/
    hooks/
    components/
    api/
```

Ventajas:
- ownership claro
- menos acoplamiento
- escala mejor
- features autocontenidas

### Layer-based

```txt
screens/
components/
services/
hooks/
```

Problemas:
- carpetas gigantes
- imports cruzados
- difícil ownership

Feature-based suele funcionar mejor en apps medianas/grandes.
