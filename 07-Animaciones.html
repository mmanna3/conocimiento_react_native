Reanimated / Animations

1. ¿Por qué Reanimated es más performante?

Reanimated 2+ ejecuta animaciones en el UI thread via worklets ( código JS compilado a runtime nativo ), sin round-trip JS↔native por frame.

El Animated API clásico corre en JS thread — cada frame serializa valores por el bridge → jank cuando JS está ocupado.

Reanimated también integra layout animations, shared element transitions, y sync con Gesture Handler en el mismo thread.

2. ¿Qué diferencia hay entre Animated y Reanimated?

Animated (RN core)Reanimated 2/3
JS thread (mayoría)UI thread worklets
API useNativeDriver limitadaTransform, opacity, layout, gestures
Menos setupBabel plugin requerido
Suficiente para fades simplesScroll-linked, gestures complejos

Default en apps nuevas: Reanimated para cualquier animación interactiva o 60fps crítico.

3. ¿Qué corre en UI thread?

  • Worklets de Reanimated ('worklet' directive).
  • Gesture Handler callbacks configurados con Reanimated.
  • Layout animations de Reanimated.
  • Animaciones nativas con useNativeDriver: true (solo transform/opacity).
  • Compositor nativo iOS/Android para transforms.

JS thread: lógica de negocio, setState, fetch — no debe manejar 60fps animation loops.

4. ¿Qué son worklets?

Funciones JavaScript marcadas que Reanimated compila y ejecuta en el UI runtime (sin volver al JS thread cada frame).

const style = useAnimatedStyle(() => ({
  transform: [{ translateX: offset.value }]
}));

Acceden a SharedValue (.value) sincronizados entre threads. No pueden usar hooks React ni closures no serializables arbitrariamente.

5. ¿Qué animaciones hiciste?

Prepará ejemplos concretos (adaptá):

  • Bottom sheet draggable con snap points (Gesture Handler + Reanimated).
  • Parallax header en scroll (useAnimatedScrollHandler).
  • Shared element transition entre list → detail.
  • Skeleton shimmer (loop en UI thread).
  • Swipe-to-delete row con threshold y spring back.
  • Animated tab indicator siguiendo pager.

Mencioná FPS antes/después si tenés números.

6. ¿Cómo evitar dropped frames?

  • Animar solo transform/opacity en UI thread.
  • Evitar layout animations en listas largas simultáneas.
  • No disparar setState por frame — usar SharedValues.
  • Reducir sombras/blur durante animación.
  • runOnJS solo para side effects puntuales, no cada frame.
  • Profiler: Reanimated perf monitor, Xcode Core Animation FPS.

7. ¿Cómo debuggear una animación lenta?

  1. Confirmar que corre en UI thread (¿worklet o Animated sin native driver?).
  2. ¿JS thread bloqueado simultáneamente? → Flipper performance.
  3. Simplificar: aislar una prop animada.
  4. Revisar re-renders del componente padre durante animación.
  5. Android: overdraw, elevation; iOS: offscreen rendering con cornerRadius+shadow.

8. ¿Cuándo NO usar animaciones complejas?

  • Listas con cientos de items animados individualmente.
  • Devices gama baja target — preferir fades simples.
  • Flujos de accesibilidad (Reduce Motion activado — respetar AccessibilityInfo.isReduceMotionEnabled).
  • Donde no aportan UX clara — animación por animación distrae.
  • Critical path loading — priorizar content over polish.

9. ¿Cómo sincronizar gestures y animaciones?

react-native-gesture-handler + Reanimated:

const gesture = Gesture.Pan()
  .onUpdate(e => { translateX.value = e.translationX; })
  .onEnd(e => { translateX.value = withSpring(0); });

Gesture Handler corre reconocimiento nativo; callbacks en worklets actualizan SharedValues que useAnimatedStyle refleja sin setState. Usar simultaneousHandlers, waitFor para gestos anidados (scroll + pan).

Topics a mencionar:

  • Conflicto scroll vs swipe — activeOffsetX, failOffsetY.
