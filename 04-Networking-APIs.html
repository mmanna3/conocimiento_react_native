04 · Networking

Networking / APIs

1. ¿Cómo manejás requests concurrentes?

  • Promise.all — paralelo cuando no hay dependencias.
  • Promise.allSettled — cuando algunos pueden fallar sin bloquear otros.
  • React Query deduplica requests con misma query key automáticamente.
  • Limitar concurrencia con pools (p-queue) si hay rate limits.
  • Priorizar: critical path first, defer analytics/secondary fetches.

2. ¿Cómo cancelás requests?

AbortController (fetch nativo y axios v0.22+):

const controller = new AbortController();
fetch(url, { signal: controller.signal });
// cleanup: controller.abort();

React Query cancela automáticamente queries al unmount o cuando query key cambia. En useEffect, abort en cleanup para evitar setState on unmounted component y race conditions (respuesta vieja sobrescribe nueva).

3. ¿Cómo manejás retries?

  • Exponential backoff con jitter para errores transitorios (5xx, network timeout).
  • No retry en 4xx (excepto 429 con Retry-After).
  • React Query: retry: 3, retryDelay configurable.
  • Idempotency keys en mutaciones POST críticas.
  • UI: mostrar retry manual después de N intentos automáticos.

4. ¿Cómo manejás auth tokens?

  • Access token corto en memoria o secure storage.
  • Interceptor request: attach Authorization: Bearer.
  • Nunca en query params ni logs.
  • Logout: clear storage + invalidate React Query cache + reset navigation.
  • Biometric unlock para reabrir token desde Keychain si aplica.

5. ¿Cómo manejás refresh token expiration?

Patrón refresh token rotation:

  1. 401 en request → interceptor pausa cola de requests.
  2. Intenta refresh con refresh token (single flight — solo un refresh concurrente).
  3. Éxito → guardar nuevos tokens, replay requests en cola.
  4. Fallo (refresh expirado/revocado) → logout forzado, redirect login.

Cuidado: race conditions con múltiples 401 simultáneos — usar mutex/queue. Refresh token en secure storage, rotación server-side.

6. ¿Cómo manejás interceptors?

Axios/fetch wrapper con cadenas:

  • Request: auth header, correlation ID, locale, timing start.
  • Response: unwrap envelope, normalize errors, refresh token logic.
  • Error: map HTTP codes a AppError types, report to Sentry (sin tokens).

Mantener interceptors delgados — lógica compleja en authService. Testeable mockeando el client.

7. ¿Qué harías si la API es lenta?

  • UX: skeletons, optimistic UI, stale-while-revalidate.
  • Cache agresivo para datos que cambian poco.
  • Pagination/infinite scroll en lugar de payloads gigantes.
  • Prefetch en hover/focus (web) o on navigation intent (RN).
  • CDN/edge para assets; GraphQL field selection si over-fetching.
  • Timeout + feedback al usuario; cancelación si navega away.
  • Escalar con backend team: profiling, N+1 queries, compression (gzip/brotli).

8. ¿REST vs GraphQL?

REST: simple, cache HTTP estándar, tooling maduro. Over/under-fetching posible. Bueno para APIs CRUD estándar.

GraphQL: cliente pide exactamente lo que necesita; un endpoint; tipado fuerte con schema. Complejidad en server (resolvers, N+1 con DataLoader), caching más difícil que REST HTTP cache.

En mobile: GraphQL brilla con pantallas agregadas (home feed) y versionado de campos; REST brilla con simplicidad y TanStack Query. Elegí según equipo backend y shape de datos.

9. ¿Cómo manejás versionado de APIs?

  • URL versioning (/v2/users) o header (Accept-Version).
  • App envía X-App-Version — backend puede responder distinto o forzar upgrade.
  • Contratos: OpenAPI/GraphQL schema con changelog.
  • Deprecation window — soportar N y N-1 en transición.
  • Feature flags para migrar clientes gradualmente.
  • Codegen desde schema para detectar breaking changes en CI.

10. ¿Cómo debuggeás problemas de networking?

  • Flipper Network plugin / Reactotron / Charles Proxy / mitmproxy.
  • Log correlation IDs end-to-end con backend.
  • Verificar SSL pinning no bloquea debug certs en dev.
  • Compare request/response dev vs prod (headers, body encoding).
  • Android cleartext traffic / iOS ATS exceptions en dev.
  • Reproducir con curl/Postman mismo payload que la app.
  • Sentry breadcrumbs con endpoint, status, duration (sin body sensible).
