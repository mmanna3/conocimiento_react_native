iOS / Xcode / Fastlane

1. ¿Qué hace Fastlane?

Fastlane automatiza tareas de release mobile: builds, screenshots, signing, upload a TestFlight/App Store, beta distribution.

Lanes comunes: match (certificados/profiles en repo cifrado), gym (build), pilot (TestFlight), deliver (App Store metadata).

Alternativa moderna: EAS Build/Submit de Expo que abstrae mucho de esto. Fastlane sigue estándar en bare RN enterprise con control fino.

2. ¿Cómo automatizar releases?

  1. CI trigger en tag o merge a release branch.
  2. Bump version/build number automático.
  3. Run tests + lint.
  4. Build signed IPA (Fastlane/EAS).
  5. Upload TestFlight → QA approval → phased release App Store.
  6. Slack notification + changelog desde commits convencionales.

Signing certs via match o App Store Connect API keys (no password 2FA manual en CI).

3. ¿Qué son provisioning profiles?

Archivo que vincula: App ID + certificado de signing + device IDs (development/ad hoc) o App Store distribution. Le dice a iOS que tu app está autorizada para instalarse/ejecutarse con esas capabilities (push, associated domains, etc.).

Tipos: Development, Ad Hoc, App Store, Enterprise. Expiran — renovación anual típica con certificados.

4. ¿Qué es un signing certificate?

Certificado criptográfico (Apple Development / Distribution) que firma el binary. iOS verifica la firma antes de ejecutar. Development cert para debug en devices registrados; Distribution para TestFlight y App Store.

Private key en Keychain local o CI (match encrypted repo). Perder la key = regenerar cert y reprovisionar.

Bugs que solo aparecen en release: ProGuard-like stripping, timing, Hermes differences — siempre testear release builds antes de store.

6. ¿Cómo investigás un crash de iOS?

  • Xcode Organizer → Crashes (symbolicated con dSYM).
  • Subir dSYM a Sentry/Crashlytics en CI.
  • Reproducir con Address Sanitizer / Zombie Objects en debug.
  • Log console + Instruments (Zombies, Leaks).
  • Identificar si es nativo (objc exception) vs JS (Hermes stack).

7. ¿Qué experiencia tenés tocando código nativo?

Framework de respuesta honesta:

  • Bridge modules — exponer SDK nativo a JS (Swift/ObjC).
  • Config nativa — Info.plist, entitlements, AppDelegate changes.
  • Debugging — crashes en módulos third-party, pod conflicts.
  • Codegen / TurboModules — specs para New Architecture.

Si experiencia limitada: “Sé leer y modificar integraciones existentes, colaboro con iOS dev para features nativas nuevas, domino el pipeline de build/release.”

8. ¿Cómo funciona CocoaPods?

Gestor de dependencias iOS. Podfile declara pods → pod install genera .xcworkspace con pods integrados. RN autolinking registra pods de node_modules automáticamente.

Problemas comunes: version conflicts, stale Pods cache, M1/M2 arch issues (ffi, pod repo update), deployment target mismatch. Fix: pod deintegrate && pod install, limpiar DerivedData.

9. ¿Qué problemas típicos viste en iOS builds?

  • Signing/provisioning profile expired or wrong bundle ID.
  • Pod version conflict post RN upgrade.
  • Module 'React' not found — header search paths.
  • Bitcode/architecture warnings (Apple Silicon simulators).
  • Privacy manifest / required reason APIs (Apple compliance 2024+).
  • Associated domains / push capability missing in entitlements.
