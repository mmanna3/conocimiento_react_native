Android / Gradle

1. ¿Qué es Gradle?

Gradle es el sistema de build de Android (y RN Android). Usa Groovy/Kotlin DSL para definir tasks: compilar, empaquetar, firmar, dependencias, variants.

En RN: android/build.gradle (project level), android/app/build.gradle (app module), settings.gradle para autolinking.

2. ¿Qué hace el build.gradle?

App-level build.gradle define:

  • applicationId, versionCode, versionName
  • minSdkVersion, compileSdkVersion, targetSdkVersion
  • Dependencies (implementation, etc.)
  • Signing configs (debug/release)
  • Build types y product flavors
  • ProGuard/R8 rules

3. ¿Qué diferencia hay entre implementation/api?

  • implementation — dependencia interna; no expuesta transitivamente a quien dependa de tu módulo. Faster builds, encapsulation.
  • api — expuesta en API pública del módulo; consumers también la ven en classpath.

Default preferido: implementation. Usar api solo si types de la dep aparecen en tu API pública.

4. ¿Cómo funcionan build variants?

Variant = build type × product flavor. Ej: debug + staging → stagingDebug.

  • Build types: debug, release (signing, minify, debuggable).
  • Product flavors: staging, prod — distintos applicationId, resources, API URLs via resValue/buildConfigField.

RN: flavors para ambientes; correr ./gradlew assembleStagingRelease.

5. ¿Cómo investigás un crash Android?

  • Logcat filtrado por package / FATAL EXCEPTION.
  • Play Console → Android Vitals → stack traces (deobfuscated con mapping file).
  • Reproducir en emulator/device con Android Studio attached.
  • Diferenciar JS crash (Hermes red box) vs native (Java/Kotlin exception).
  • Subir ProGuard mapping a Crashlytics/Sentry en CI release build.

6. ¿Qué problemas típicos viste con Android builds?

  • Duplicate class / dependency version conflicts.
  • minSdk vs lib requiring higher SDK.
  • Gradle/JDK version mismatch post RN upgrade.
  • Out of memory en CI (org.gradle.jvmargs).
  • 64K method limit (multidex).
  • Autolinking failures — package not found.
  • Keystore/password issues en release signing.

7. ¿Cómo reducir build times?

  • Gradle daemon + configuration cache + parallel builds.
  • Cache en CI (gradle cache, node_modules, pods).
  • Prebuilt RN artifacts donde aplique.
  • Modularización — no rebuild todo por cambio JS-only (OTA).
  • EAS remote builds con cache layers.
  • Evitar clean innecesario en CI.
  • Upgrade Gradle/AGP con benchmarks.

8. ¿Qué problemas de dependencias viste?

  • Transitive deps trayendo versiones incompatibles (force resolution).
  • AndroidX vs support library legacy.
  • Kotlin version mismatch entre libs.
  • RN upgrade rompiendo native modules sin mantenimiento.
  • npm vs gradle — misma lib linked dos veces diferente versión.

Fix: ./gradlew app:dependencies, dependencyInsight, resolutions in root build.gradle, patch-package temporal, fork o reemplazo de lib.
