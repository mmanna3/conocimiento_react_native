Performance en React

1. ¿Cómo detectás renders innecesarios?

  • React DevTools Profiler — grabá una interacción, mirá qué componentes re-renderizaron y cuánto tardaron.
  • “Highlight updates” — visual feedback de re-renders en pantalla.
  • why-did-you-render — librería para loggear renders evitables.
  • React Native: Flipper Performance, Systrace, Reactotron.

Señales: un click en un botón re-renderiza todo el árbol; listas completas parpadean; FPS cae en scroll. Compará renders vs commits — muchos renders baratos pueden ser OK; pocos renders caros no.

2. ¿Qué herramientas usás para medir performance?

Web/React: React DevTools Profiler, Chrome Performance tab, Lighthouse, Web Vitals (LCP, INP, CLS).

React Native: Flipper (layout, network, Hermes debugger), Xcode Instruments (Time Profiler, Allocations), Android Studio Profiler, Metro bundle analyzer, Reanimated performance monitor.

Producción: Sentry Performance, Firebase Performance, Datadog RUM, custom traces con InteractionManager en RN.

Senior tip: medí en dispositivo real de gama media/baja, no solo simulador en Mac M-series.

3. ¿Qué problemas viste en producción?

Ejemplos reales comunes (adaptá con tu experiencia):

  • Context con objeto nuevo cada render → toda la app re-renderiza en cada keystroke.
  • Lista de 500 items sin virtualización → scroll a 30 FPS.
  • Imágenes sin cache/size adecuado → OOM en Android gama baja.
  • useEffect con fetch sin cancelación → race conditions y memory leaks.
  • Redux selectors sin memoización → recalcular filtros pesados cada action.

En entrevista: contá un caso concreto con síntoma → diagnóstico → fix → métrica de mejora.

4. ¿Cómo optimizar listas grandes?

  • Virtualización — FlatList / FlashList en RN; react-window / react-virtuoso en web.
  • getItemLayout — si items tienen altura fija, evita medición dinámica.
  • keyExtractor estable con IDs reales.
  • renderItem memoizado — React.memo en el row component.
  • windowSize, maxToRenderPerBatch, removeClippedSubviews — tunear según caso.
  • Evitar inline functions/objetos en props del row; separar header/footer.
  • Pagination o infinite scroll en lugar de cargar 10k items.

5. ¿Qué problemas puede generar Context API?

  • Re-renders en cascada — cualquier cambio en value re-renderiza todos los consumers, aunque solo les interese una slice.
  • Value inestable — value={{ user, theme }} recreado cada render.
  • God context — un solo context para toda la app.
  • Mezclar server state — fetch + cache en Context en lugar de React Query.

Mitigaciones: split contexts (state vs dispatch), selectors con use-context-selector, memoizar value, o migrar a Zustand/Redux para state frecuente.

6. ¿Cuándo dividir componentes?

Dividí cuando:

  • Partes del UI re-renderizan por state distinto — aislar el state local al subtree que lo necesita.
  • Un bloque es costoso y puede memoizarse independientemente.
  • Mejora legibilidad/testabilidad sin sacrificar cohesión.
  • Necesitás lazy loading de rutas o features (React.lazy).

No dividas prematuramente — demasiados componentes micro aumentan props drilling. Balance: cohesión de dominio + aislamiento de renders.

7. ¿Qué hace el batching de React?

Batching agrupa múltiples setState en un solo re-render para eficiencia.

React 17: batching solo en event handlers de React.

React 18 (Automatic Batching): también en setTimeout, promises, native event handlers, fuera del árbol React en algunos casos.

flushSync() fuerza render síncrono cuando necesitás leer el DOM actualizado inmediatamente (casos raros).

En RN con React 18+ el batching automático aplica igual — menos renders por múltiples updates en un tick.

8. ¿Qué problemas de memoria viste?

  • Listeners/subscriptions sin cleanup en useEffect.
  • Closures reteniendo referencias grandes (arrays completos en callbacks).
  • Caches sin límite (imágenes, maps globales).
  • Navigation stacks acumulando screens con state pesado.
  • Timers/intervals activos tras unmount.
  • En RN: bridges con muchos eventos, Hermes heap growth por leaks en módulos nativos.

Diagnóstico: Xcode Allocations, Android Memory Profiler, Hermes heap snapshot. Fix: cleanup riguroso, WeakMap donde aplique, limitar cache LRU.
