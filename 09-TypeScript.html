TypeScript

1. ¿Por qué usar TypeScript?

  • Errores en compile-time vs runtime en prod.
  • Autocomplete e IntelliSense — velocity en codebases grandes.
  • Refactors seguros (rename, move) con confidence.
  • Contratos explícitos entre módulos/equipos.
  • Codegen desde OpenAPI/GraphQL integra naturalmente.
  • RN New Architecture Codegen requiere typed specs.

Costo: setup inicial, curva generics, occasional fighting the compiler — ROI positivo en equipos >2 devs y apps long-lived.

2. ¿Qué diferencia hay entre type e interface?

interface: extend/merge (declaration merging), mejor para object shapes públicos de libs, implements en clases.

type: unions, intersections, mapped types, tuples, primitivos — más expresivo para composición.

type Status = 'idle' | 'loading' | 'error';
interface User { id: string; name: string; }

Convención moderna: interface para props de componentes y APIs de objetos; type para unions y utility compositions. En la práctica, muchas bases usan solo type por consistencia.

3. ¿Qué son generics?

Parámetros de tipo — funciones/clases reutilizables sin perder type safety:

function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

En React: useState<User | null>(null), FlatList<Item>, API responses tipados. Constraints: <T extends { id: string }>.

4. ¿Qué son utility types?

Tipos built-in para transformar otros tipos:

  • Partial<T> — todos opcionales.
  • Pick<T, K> / Omit<T, K> — subset.
  • Record<K, V> — mapa keyed.
  • ReturnType<typeof fn> — infer return.
  • Parameters<typeof fn>
  • NonNullable<T>, Extract, Exclude

Evitan duplicar definiciones — DRY en tipos de API y forms.

5. ¿Cómo tipar hooks?

function useUser(id: string) {
  const [user, setUser] = useState<User | null>(null);
  const [error, setError] = useState<Error | null>(null);
  // ...
  return { user, error, isLoading } as const;
}

type UseUserReturn = ReturnType<typeof useUser>;

Custom hooks: exportar return type explícito si es API pública. Generics en hooks reutilizables: useAsync<T>(fn: () => Promise<T>).

6. ¿Cómo tipar APIs?

  • Generar desde OpenAPI: openapi-typescript, Orval.
  • Zod schema → infer: type User = z.infer<typeof UserSchema> — runtime validation + types.
  • Discriminated unions para responses: { ok: true, data: T } | { ok: false, error: E }.
  • Tipar axios/fetch wrapper genérico: get<User>('/users/1').

Nunca confiar solo en types — validar en runtime datos externos (Zod en boundaries).

7. ¿Qué problemas reales resolviste con TS?

Ejemplos para entrevista:

  • Refactor masivo de navigation params — compiler encontró 40 call sites rotos.
  • API backend cambió field optional → error en compile antes de release.
  • Typed Redux slices / RTK Query codegen eliminó mismatches action payload.
  • Strict null checks atrapó crashes de undefined.id en prod.

8. ¿Qué cosas de TS pueden empeorar DX?

  • Over-engineering de types (generics anidados ilegibles).
  • strict: false o any everywhere — falsa sensación de safety.
  • Fighting third-party types incorrectos (@types desactualizados).
  • Build lento en monorepos gigantes sin project references.
  • Tipar mocks de tests verboso — usar Partial, satisfies, type assertions acotadas.
  • Migration parcial JS/TS — boundaries inconsistentes.

Balance: strict mode on, pragmatismo con unknown over any, codegen donde escala.
