Accesibilidad

1. ¿Cómo manejás accessibility en mobile?

  • Labels: accessibilityLabel, accessibilityHint en elementos interactivos.
  • Roles: accessibilityRole="button", headers, links.
  • State: accessibilityState={{ selected, disabled, checked }}.
  • Touch targets mínimo 44×44 pt (WCAG / HIG).
  • Color contrast — no solo color para estado (añadir icon/text).
  • Dynamic Type — respetar font scaling (allowFontScaling, layouts flexibles).
  • Reduce Motion — simplificar animaciones.
  • Focus order lógico para VoiceOver/TalkBack.

Accesibilidad no es feature final — integrar en design system desde el inicio.

2. ¿Qué features de accessibility usaste?

  • VoiceOver (iOS) / TalkBack (Android) testing manual.
  • accessibilityLiveRegion para anuncios dinámicos (toast, errors).
  • importantForAccessibility para ocultar decoración.
  • Grouped elements: accessible={true} en container vs hijos.
  • testID separado de accessibilityLabel (testID no es para a11y).
  • React Native ARIA props en New Architecture / web compat.
  • Haptic feedback complementario, no sustituto de labels.

3. ¿Cómo testear accessibility?

  • Manual: recorrer app con VoiceOver/TalkBack activado — ¿cada acción es anunciada?
  • Automated: axe-core (web), eslint-plugin-react-native-a11y.
  • Checklist: contrast analyzers, font scale al 200%.
  • User testing con personas que usan assistive tech — gold standard.
  • Incluir a11y en Definition of Done y QA regression.

iOS Accessibility Inspector, Android Accessibility Scanner apps.
